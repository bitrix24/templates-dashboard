# i18n

The app is localized across **19 locales** via `@nuxtjs/i18n` (strategy
`no_prefix`). **No user-facing string may be hard-coded.**

## Files

- `i18n/i18n.ts` — `contentLocales`: the canonical list of locales (`code`, `name`,
  `file`). Adding a locale means adding an entry here **and** a `locales/<code>.json`.
- `i18n/locales/en.json` — **the source of truth.** Author every key here first.
- `i18n/locales/<code>.json` — one per locale (`ru`, `de`, `fr`, `ua`, `ja`, …),
  generated/filled from `en.json`.

Keys are nested and namespaced by area, e.g.:

```json
{
  "page": {
    "index": { "seo": { "title": "Home" } }
  }
}
```

## Usage in components

```ts
const { t } = useI18n()
// ...
useHead({ title: t('page.customers.seo.title') })
```

```vue
<template>
  <B24Button :label="t('page.customers.action.add')" />
</template>
```

- SEO: prefer `t(...)` inside `useHead` / `useSeoMeta`.
- Do not concatenate translated fragments; add a full key per phrase. Use i18n
  interpolation/pluralization for variables rather than string building.
- The current locale code is available as `locale` from `useI18n()`; b24jssdk
  formatting (currency/date) is keyed off it — see `useDealStats`.

## Workflow: adding or changing text

1. Add / edit the key in `i18n/locales/en.json`.
2. Reference it with `t('...')` — never inline the literal.
3. Mirror the key into every other `i18n/locales/<code>.json`. `en.json` is the
   source of truth; there is no automated sync tool — add the same key path to each
   locale file (translated, or copied from `en.json` as a placeholder) and review
   the diff before committing. Keep the key set identical across all locale files.

## Requirements (localization pass)

The template is being audited so that **every** page is fully localized (tracked
in issue #7). These are the finalized rules — apply them whenever you touch a page:

- [ ] **No literal user-facing strings** in template or script — all via `t()`.
      This includes strings built in composables (e.g. stat card titles/descriptions
      in `useDealStats`), toast titles, SEO titles, and aria labels.
- [ ] **Namespace keys** sensibly: `page.<name>.*` for page-specific text, a feature
      namespace (`dealStats.*`) for composable/feature text, `common.*` for shared
      strings (e.g. `common.error`).
- [ ] **Interpolate**, don't concatenate: `t('...', { currency })` with `{currency}`
      in the message — never build strings from translated fragments.
- [ ] **Mirror every key** into all `i18n/locales/*.json` so the key sets are
      identical across locales (there is no automated sync tool). Provide a real
      translation where you can; an English placeholder otherwise (refine later).
- [ ] **Remove stale keys** from every locale when the text they served is deleted.
- [ ] Strings passed to the **Bitrix24 REST API** as payload (e.g. a placement
      `TITLE`) are not viewer-facing UI and stay out of the i18n catalog.

### Fallback

`i18n/i18n.config.ts` sets `fallbackLocale: 'en'`, so a key missing in the active
locale degrades to English rather than showing the raw key path. This is a safety
net, **not** a substitute for mirroring keys — still add every key to every locale.
